# andrew.kincaid.io

Personal resume site + PDF generator for Andrew Kincaid.

Single source of truth → web page + designed PDF → deployed to Firebase Hosting behind a global CDN on `andrew.kincaid.io` (canonical) and `andrew.kinca.id` (mirrors → 301 to canonical).

---

## Stack

| Layer       | Choice                        | Why                                                                                 |
| ----------- | ----------------------------- | ----------------------------------------------------------------------------------- |
| Framework   | **Astro 5**                   | Static-first, zero client JS by default, great DX, dead simple deploys.             |
| Styling     | Plain CSS + design tokens     | The site is content-driven; a utility framework would add weight without payoff.    |
| Typography  | Instrument Serif + Inter      | Editorial display serif + workhorse sans, both self-hosted via Fontsource.          |
| Content     | `src/content/resume.ts`       | Typed single source of truth, rendered by both the web page and the print page.     |
| PDF         | Playwright → `/resume/print`  | Designed print page, rendered by headless Chromium. No "print the webpage" hacks.   |
| OG image    | Playwright → `/og` screenshot | Same engine already on hand; always matches current content.                        |
| Hosting     | Firebase Hosting (GCP)        | Free tier is generous, global CDN, SSL auto-provisioned, custom domains, instant.   |
| CI/CD       | GitHub Actions                | Build + Playwright + deploy on every push to `main`; preview channels for PRs.      |

**Why Firebase and not Cloud Run / Cloud Storage + Load Balancer?** Firebase Hosting is Google's static-site CDN product; it's cheaper, faster, and far lower-maintenance than rolling your own GCS + Cloud CDN + HTTPS load balancer. The project still lives under your GCP `kincaid-resume` project — Firebase projects and GCP projects are the same thing.

## Local development

```bash
npm install
npm run dev          # http://localhost:4321
```

Useful routes:

- `/` — the live web resume
- `/resume/print` — the print-optimized page that becomes the PDF
- `/og` — the social share image (1200×630)

## Build + PDF

```bash
npm run build        # Astro static build into ./dist
npm run pdf          # boots preview, generates PDF + og-image, copies both into ./dist and ./public
npm run build:full   # both, in order
```

`npm run pdf` requires Playwright's Chromium to be installed once:

```bash
npx playwright install chromium
```

## Updating resume content

Everything — experience, highlights, skills, credentials, links — lives in [`src/content/resume.ts`](./src/content/resume.ts). Edit that file, then:

```bash
npm run build:full
```

The web page and PDF will regenerate together. No hunting through components.

### Tailoring the resume to a specific job

Recommended workflow:

1. Branch: `git checkout -b tailor/<company>`
2. Edit `src/content/resume.ts` — reorder bullets, sharpen the summary, swap the headline.
3. `npm run build:full` and review `public/andrew-kincaid-resume.pdf`.
4. Either ship the branch to production, or export the PDF alone and keep the branch offline as your archive for that role.

Because content is structured data (not prose in a Word doc), tailoring is a quick editing pass, not a reformat.

## Deployment

### First-time setup (manual, do this once)

These are the manual steps I can't do for you:

1. **Install Firebase CLI** (if you don't have it):
   ```bash
   npm install -g firebase-tools
   firebase login
   ```

2. **Confirm your GCP project exists** and Firebase is enabled on it:
   ```bash
   firebase projects:list
   # you should see: kincaid-resume
   ```
   If the project exists in GCP but doesn't show up here, enable Firebase on it:
   https://console.firebase.google.com/ → Add project → Select existing GCP project → pick `kincaid-resume`.

3. **Create two Hosting sites** inside the project — one per domain:
   ```bash
   firebase hosting:sites:create kincaid-resume         # for andrew.kincaid.io
   firebase hosting:sites:create kincaid-resume-mirror  # for andrew.kinca.id
   ```
   (If `kincaid-resume` already exists as the default site, the first call will be idempotent / harmless.)

4. **Bind the deploy targets** (already configured in `.firebaserc`, this just persists them):
   ```bash
   firebase target:apply hosting primary kincaid-resume
   firebase target:apply hosting mirror kincaid-resume-mirror
   ```

5. **Add custom domains**. In the Firebase Console → Hosting:
   - On the `kincaid-resume` site, add `andrew.kincaid.io`.
   - On the `kincaid-resume-mirror` site, add `andrew.kinca.id`.

   Firebase will give you DNS records (usually two `A` records per domain). Add them to each domain's DNS provider:
   - `kincaid.io` DNS: add `A` records for host `andrew` pointing at the IPs Firebase provides for the primary site.
   - `kinca.id` DNS: add `A` records for host `andrew` pointing at the IPs Firebase provides for the mirror site.

   SSL is auto-provisioned by Firebase once DNS resolves; this usually takes 15–60 minutes.

6. **Wire GitHub Actions**:
   ```bash
   # generate a service-account credential for CI
   firebase init hosting:github
   ```
   This creates a Google Cloud service account, stores a JSON key in your repo's secrets as `FIREBASE_SERVICE_ACCOUNT_KINCAID_RESUME` (or similar), and writes a workflow file. You can delete the workflow file it adds — we already have one at `.github/workflows/deploy.yml`. Just confirm the **secret name matches what the workflow expects**: the workflow reads `secrets.FIREBASE_SERVICE_ACCOUNT`. Rename the secret or update the workflow to match.

### Ongoing deploys

Every push to `main` builds, generates the PDF, and deploys to production automatically. To deploy by hand:

```bash
npm run deploy
# equivalent to:
# npm run build:full && firebase deploy --only hosting
```

Pull requests deploy to a 7-day Firebase preview channel.

## DNS redirect behavior

- `andrew.kincaid.io` — **canonical**. All traffic lands here.
- `andrew.kinca.id` — mirror. 301-redirects path-preservingly to the canonical host.

That redirect is declared in [`firebase.json`](./firebase.json) under the `mirror` target. If you ever want the mirror to also serve content directly (e.g. for A/B testing), flip it to the same config as `primary`.

## Cost expectations

Firebase Hosting free tier:

- 10 GB stored
- 360 MB/day of transfer from the CDN

The whole site including fonts and PDF weighs under 5 MB. To come anywhere close to hitting the paid tier you'd need tens of thousands of visitors per day. Practical cost: **$0/month**.
